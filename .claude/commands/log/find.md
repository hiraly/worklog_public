---
description: "課題ログを検索する（自然言語ベース）。index.yml 検索と全文検索を柔軟に使い分ける"
---

あなたは「検索係」です。ユーザーのクエリに応じて、適切な方法で課題ログを検索してください。

## 0) 重要ルール
- **自然言語で柔軟に対応**する（形式的なフラグは不要）
- クエリの意図を理解して、適切な検索方法を選ぶ
- 結果は簡潔に（該当箇所を短く引用）

## 1) 入力（自然言語ベース）

ユーザーは自然言語でクエリを入力します：

```
/log/find タイムアウト
/log/find 12月の決定事項でキャッシュに関するもの
/log/find 繰り返しハマっていること
/log/find api-timeout-fix 課題で未解決の疑問
```

### クエリから推定すべき情報

**検索範囲**：
- 「〜課題で」「〜課題の」→ 該当課題のみ
- 明示がなければ → 全課題

**時間範囲**：
- 「今日」「本日」→ 当日
- 「今週」→ 直近7日
- 「12月」「2025-12」→ 該当月
- 「12月以降」「2025-12-01以降」→ 指定日以降
- 明示がなければ → 全期間

**検索対象**：
- 「決定事項」「決めたこと」→ [decision] のみ
- 「疑問」「わからないこと」→ [why] のみ
- 「躓き」「ハマったこと」→ [stuck] のみ
- 「学び」「理解できたこと」→ [learned] のみ
- 「根拠」「ソース」→ src: 含む行
- 明示がなければ → 全タグ

**検索モード**：
- 概要検索（高速）：index.yml から検索（title, tags, key_decisions, result_summary）
- 詳細検索：README 全文から検索
- デフォルト：クエリに応じて自動選択
  - 簡単なキーワード検索 → まず index.yml、ヒットしなければ全文検索
  - タグ指定や詳細条件 → 全文検索

## 2) 検索の実装

### 2.1 概要検索（index.yml）
1. `worklog/index.yml` が無ければ `/log/index` を実行して生成
2. 以下フィールドを対象に検索：
   - title, slug, tags
   - sources_summary
   - key_decisions
   - result_summary
3. ヒット上位10件を返す

### 2.2 詳細検索（README 全文）
1. 対象課題の README.md を列挙
   - 時間範囲でフィルタ（フォルダの `YYYY-MM-DD` で判定）
   - 課題指定があれば該当課題のみ
2. `# 4. 試行錯誤ログ（時系列 / raw）` セクションを抽出
3. タグでフィルタ（指定があれば）
4. キーワードで検索（部分一致）
5. ヒット上位20件を返す（超える場合は件数と絞り込み提案）

## 3) 出力フォーマット

### 3.1 概要検索の出力
```
## 検索結果（index.yml から）

- <title> | <slug> | status:<status> | visibility:<visibility>
  path: <path>
  決定: <key_decision の1件>
  結果: <result_summary>

... (最大10件)

該当: N件
```

### 3.2 詳細検索の出力
```
## 検索結果（README 全文から）

- <slug> (<date>) <path>
  → <該当行（120文字程度で切る）>

- <slug> (<date>) <path>
  → <該当行>

...（最大20件）

該当: N件
※ 20件を超える場合は絞り込みを提案
```

## 4) 特殊な検索パターン

### 繰り返しパターンの検索
- 「繰り返し」「2回以上」「何度も」→ 同じキーワードが複数回出現
- 例：「繰り返しハマっていること」→ [stuck] で同じキーワードが2回以上

### 未解決の検索
- 「未解決」「TODO」→ evidence: TODO や抜粋が TODO のもの
- 例：「未解決の疑問」→ [why] があって対応する [learned] がない

### タグの組み合わせ
- 「〜から〜への変化」→ タグのペアを探す
- 例：「疑問が解決されたもの」→ [why] → [learned] のペア

## 5) 結果が多い場合の対応
- 20件を超える場合：
  1. 件数を表示
  2. 絞り込み提案（時間範囲、タグ、課題を絞る）
  3. 上位20件のみ表示

## 使用例（自然言語入力）

### 例1：シンプルなキーワード検索
```
ユーザー: "/log/find タイムアウト"
→ まず index.yml で「タイムアウト」を検索
→ ヒットが少なければ README 全文も検索
```

### 例2：タグ指定
```
ユーザー: "/log/find 決定事項でキャッシュに関するもの"
→ [decision] タグの行から「キャッシュ」を検索
```

### 例3：時間範囲指定
```
ユーザー: "/log/find 12月以降の疑問"
→ 2025-12-01 以降のフォルダから [why] を抽出
```

### 例4：課題指定
```
ユーザー: "/log/find api-timeout-fix 課題で未解決の疑問"
→ api-timeout-fix フォルダの [why] で、対応する [learned] がないもの
```

### 例5：繰り返しパターン
```
ユーザー: "/log/find 2回以上ハマったこと"
→ [stuck] で同じキーワードが複数回出現するもの
```

### 例6：根拠不足
```
ユーザー: "/log/find 根拠が TODO の決定事項"
→ [decision] で evidence: TODO のもの
```
